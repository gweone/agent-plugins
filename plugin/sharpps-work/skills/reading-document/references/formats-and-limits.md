# Formats and limits

What `markitdown` produces for each file type, and what to check before trusting it.
Observed with markitdown 0.1.9 on generated sample files; real documents vary, so verify
against the source for anything that matters.

These are the **defaults without plugins**. An installed plugin can change them, so check
`markitdown --list-plugins` first ([plugins](plugins.md)).

## Per format (default, without plugins)

| Type | What you get | Verify | Watch for |
|---|---|---|---|
| **PDF** (text-based) | Plain text; pages separated by a form-feed character (`\f`) | Page count = number of `\f` + 1 (with `-p`: count `## Page N` headings); the text you expect is present | **Scanned or image-only PDF: empty output.** In the test, no headings or layout were reconstructed |
| **Word** `.docx` | Headings as `#`, paragraphs, tables as pipe tables | Headings and tables present (`grep -c '^|'` counts table rows) | A table can come out with an empty header row, the real header then being the first row. Images become a truncated placeholder. Comments and tracked changes were not tested; assume they may be missing |
| **PowerPoint** `.pptx` | `<!-- Slide number: N -->` markers, titles as `#`, speaker notes under `### Notes:` | Number of slide markers = number of slides | Pictures are not described without a vision model; charts were not tested |
| **Excel** `.xlsx` | One `## SheetName` section per sheet, each a pipe table | One section per sheet you expect | The first row of every sheet becomes the table header. A formula shows its **cached** value; a formula that was never calculated (a file generated by a script and never opened in Excel) shows `NaN` |
| **HTML** or URL | Headings, bold text and tables kept | Compare with the page | A URL is fetched by `markitdown` itself (tested against a local server only) |
| **CSV** | A pipe table | Row count | Very wide or long tables: read selectively |
| **JSON / XML** | The text, unchanged (not restructured) | n/a | Use a JSON/XML parser for structured work |
| **ZIP** | Each member converted under `## File: <name>` | One section per member | Members of other types were not tested; check each one |
| **Images** (`.png`, `.jpg`) | **Empty output** by default | n/a | No text is extracted by default. An OCR plugin with a model can add it ([plugins](plugins.md)); otherwise view the image directly |

Also supported through extras but not tested here: `.xls`, Outlook `.msg`, audio and YouTube
transcripts ([setup](setup.md#extras-install-what-you-need)).

## Verification snippets

No real text (nothing extracted). Ignores blank lines and the `## Page N` headings a plugin adds:

```bash
out=/tmp/work/doc.md
grep -v -E '^(## Page [0-9]+)?[[:space:]]*$' "$out" | grep -q . || echo "NO TEXT: nothing was extracted from this file"
```

PDF page count and one page at a time:

```bash
markitdown file.pdf -o /tmp/work/file.md
echo "pages: $(( $(tr -cd '\f' < /tmp/work/file.md | wc -c) + 1 ))"
awk 'BEGIN{RS="\f"} NR==2' /tmp/work/file.md         # page 2 only
# with -p the pages are "## Page N" headings instead: grep -c '^## Page ' /tmp/work/file.md
```

Counts by type:

```bash
grep -c 'Slide number' /tmp/work/deck.md             # slides in a .pptx
grep -c '^## ' /tmp/work/book.md                      # sheets in an .xlsx
grep -c 'NaN' /tmp/work/book.md                       # uncalculated formulas or blanks
```

## Scanned PDFs and images

By default there is no text to extract. First check for an OCR-capable plugin
(`markitdown --list-plugins`, see [plugins](plugins.md)). If there is none, or it cannot run
here, say so and choose with the user: render the pages to images and look at them (for
example with poppler's `pdftoppm -r 150 -png`, if available), ask for a text-based copy, or
use an OCR route they approve. Do not summarize from a conversion with no text.

## Batch conversion

Convert each file on its own so one failure does not stop the rest, and report failures and
empty results:

```bash
mkdir -p /tmp/work/md
for f in docs/*; do
  markitdown "$f" -o "/tmp/work/md/$(basename "$f").md" 2>/dev/null || echo "FAILED: $f"
done
for m in /tmp/work/md/*.md; do
  grep -v -E '^(## Page [0-9]+)?[[:space:]]*$' "$m" | grep -q . || echo "NO TEXT: $m"
done
```

A file that fails writes no output; a scanned PDF writes an empty file (or, with a plugin,
only page headings). Both must appear in your report.

## Reading large outputs

- Get an outline first: `grep -n '^#' doc.md`, then read only the ranges you need.
- Search for the figure or term, read the lines around it, and quote from those lines.
- For tables, read the header and a few rows to learn the shape before reading more.
- Keep conclusions tied to a location (page, slide, sheet) so the user can check them.
