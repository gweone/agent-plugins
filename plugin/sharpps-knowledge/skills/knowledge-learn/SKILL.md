# knowledge-learn

This skill is self-contained for any AI agent or host that exposes only plugin skills (skill-only hosts): no agents/, references/ or filesystem reads are required. User instructions and tool permissions take precedence. Links below are optional explanation only, not loading prerequisites.

Hooks are optional reminders, never required for this skill, proof of execution/consent, or a promise of after-close/background work. Report hook/native-agent status only as observed enabled or unknown from already host-exposed metadata; never probe filesystem, configuration or environment to discover it. Do not infer host support from manifests/files, a client name or generic messaging. Hooks and subagents are optional for every host; neither is claimed without actual host exposure.

## Parent submission and subsequent review

Parent alone checks privacy, authorization, enabled learning, pinned scope/connection and actual `ClientCandidateSubmission` schema. Every candidate's `evidence_refs` must resolve to `submission.evidence[].id` aliases in that same packet. Respect advertised count and encoded UTF-8 byte bounds (current contract: at most 10 candidates, 100 evidence items, 256,000 packet bytes; live schemas/limits override templates). Use a stable task/submission idempotency key, unchanged only for identical content; changed content needs a new key. Do not silently truncate or split a write without checking schema and authorization.

Submit only through pinned `knowledge_submit_candidates`. Inspect transport AND application errors and acceptance/version receipts: tool success alone is not acceptance, approval or publication. Denial, stale state or uncertain possibly committed writes stop; no connector replay or namespace/scope failover. A documented same-connection idempotent receipt recovery is not permission for blind resubmission. Do not fall back to optional `experience_submit`, provider jobs or manual review to bypass a guard.

New candidates require a distinct evaluative review step, never extractor silent autoapproval. This independently loaded skill completes extraction/submission by leaving candidates pending; it requires no reviewer, hook or other skill to do that. A separately available knowledge-review skill may perform a subsequent cycle using its self-contained rubric and parent guards through the host-supported mechanism; if unavailable, leave the candidate pending, not brief-only review or an `evidence_supported` downgrade. Supported persisted enabled standing consent may authorize justified `approved_for_reuse` without per-candidate human confirmation only after that distinct pass and exact live policy/version/state and ACL checks.
