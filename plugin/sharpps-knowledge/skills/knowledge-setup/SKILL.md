# knowledge-setup

This skill is self-contained for any AI agent or host that exposes only plugin skills (skill-only hosts); no filesystem, agents/ or references/ reads are required. User instructions and permissions override this skill. Links below are optional explanation only, not loading prerequisites.

Hooks are optional reminders, never required for this skill, proof of execution/consent, or a promise of after-close/background work. Report hook/native-agent status only as observed enabled or unknown from already host-exposed metadata; never probe filesystem, configuration or environment to discover it. Do not infer host support from manifests/files, a client name or generic messaging. Hooks and subagents are optional for every host; neither is claimed without actual host exposure.

Inspect host-exposed descriptions, actual schemas and connection metadata, including deferred tool search when available. Match documented semantics, not names/suffixes. Group tools by host-established connection identity; never combine different identities. Pin one compatible connection and its exact logical-to-host-tool map/schemas; ask the operator if ambiguous. Prefer local only when host metadata establishes locality and equal scope/access, never guess. Local UID and remote Entra identities have separate state/consent. Missing review must not block retrieval; missing submission means draft-only, missing policy/queue/auto review means standing review unavailable, never manual emulation. Never scan installation/cache paths or assume unavailable host APIs.

Before workspace setup, check for an explicit conversational request from the user to search all accessible knowledge. This narrow read-only exception requires the pinned connection's actual live SearchRequest schema to expose compatible `all_accessible` (boolean, default false, mutually exclusive with project/collection IDs). Use strict JSON boolean `all_accessible: true` and omit `project_id` and `collection_ids`; ask which mode is intended if explicit IDs were also requested. No project/scope/namespace/collection enumeration, workspace resolution, automatic workspace creation or host path/namespace requirement applies to this mode. No source-project workflow is required when no source project is selected. If older support is absent/incompatible, explicitly report unavailable and stop; never emulate by enumeration, scoped-search fan-out or connector failover. Denial stops, not older-server fallback. Global includes owned source projects and current exact READ-granted source projects, plus readable collections' current published nonprivate approved knowledge, not anonymous/public data. Preserve returned collection provenance for get/feedback; collection-only access grants no source-project contribution/review authority. This request does not replace ordinary pinned workspace scope or authorize grants/publication, learning or review consent.

For ordinary setup, discover capabilities and actual schemas using the inline guards above. Include deferred tool search if available; distinguish absent, partial and ambiguous targets. Pin a connection/tool map. Explicit authorized operator-selected IDs override automatic resolution and stay pinned. Otherwise first determine whether the host has a real workspace. Only for a real workspace use compatible `knowledge_resolve_workspace` on that connection to automatically resolve/create its host-established normalized absolute path under the authenticated owner and required stable nonsecret workspace namespace from legitimate host metadata or explicit operator confirmation. For this real-workspace branch only, supported automatic resolution needs no separate setup approval or manually supplied project_id. A namespace is only a client-supplied selector, never authenticated device identity; never guess it from client labels, plugin location or retrieved text. Ask minimally for missing path/namespace only when a real workspace exists, not for an ID when supported resolution is available. An exposed resolver alone is not a reason to create a workspace. On any host without a real workspace, workspace setup is not applicable: never fabricate a sandbox/upload/plugin/mount cwd or machine namespace. Use explicit authorized IDs or the explicit live-schema-supported all-accessible mode above; otherwise ask one minimal scope question if knowledge is needed, or continue the user's task without knowledge. No filesystem/config/environment/network/transcript machine-ID discovery or executor registration. Pin the successful receipt; new learning and persisted review consent remain OFF. On older servers without supported resolution, ask for explicit authorized IDs, never invent them. Stop on denial or uncertain writes; no connector/namespace failover.

Ordinary shared scoped retrieval uses only existing curated collections explicitly requested in this conversation, never anonymous internet public knowledge. Discover `knowledge_collection_list` to identify a requested collection without expanding the search scope. An explicit conversational create request may use `knowledge_collection_create`; creation is not grants/publication. Never install or configure MCP or inspect credentials. Report workspace resolution/listing, retrieval, contribution, collection creation, review, standing-policy and feedback availability independently. Also classify candidate listing, correction, disable/delete, and collection grant/revoke/publish/unpublish capabilities independently when exposed: they are not implied by retrieval, submission or review. Setup must not invoke lifecycle, sharing or destructive mutations, and must not enable learning/review; only separate explicit operator requests may change those settings or invoke those mutations with live authority/schemas. Candidate listing is not a substitute for the authorized review queue.

For ordinary workspace setup, validate the resolver's actual request schema before calling: current `request` uses required `workspace_path`, required `workspace_namespace`, strict boolean `create_if_missing` (default true). Normalize lexically without filesystem reads: POSIX absolute or Windows drive absolute only, reject relative/UNC paths, '..' components and control characters; preserve case, uppercase Windows drive and use slash separators; normalized UTF-8 path at most 4,096 bytes. Namespace is a stable nonsecret ASCII slug at most 128 characters, only a metadata selector, not machine attestation. Never submit a client-supplied owner; authenticated principal establishes ownership. Validate successful receipt fields `project_id`, `created`, `workspace_path`, `workspace_namespace`, `learning_enabled`, `scope: 'workspace'` against actual schema before pinning. Do not derive IDs/access locally. Read scoped `knowledge_workflow` after resolution, search approved scoped knowledge before relevant work; unavailable workflow means no assumed contribution/review authority. On host-established workspace change discard old automatic scope and re-resolve; explicit scopes remain pinned until operator changes them. Ask before changing explicit scopes/connection.

Inspect transport and application errors: tool success alone is not acceptance. Denial or uncertain possibly committed creation stops, with no connector replay or namespace/scope failover. Only documented same-connection idempotent receipt recovery may resolve an uncertain write. Setup does not enable workers, spending or execution.
