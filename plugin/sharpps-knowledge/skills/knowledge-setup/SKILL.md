# knowledge-setup

This skill is self-contained on skill-only hosts, including Claude web; no filesystem, agents/ or references/ reads are required. User instructions and permissions override this skill. Links below are optional explanation only, not loading prerequisites.

Inspect host-exposed descriptions, actual schemas and connection metadata, including deferred tool search when available. Match documented semantics, not names/suffixes. Group tools by host-established connection identity; never combine different identities. Pin one compatible connection and its exact logical-to-host-tool map/schemas; ask the operator if ambiguous. Prefer local only when host metadata establishes locality and equal scope/access, never guess. Local UID and remote Entra identities have separate state/consent. Missing review must not block retrieval; missing submission means draft-only, missing policy/queue/auto review means standing review unavailable, never manual emulation. Never scan installation/cache paths or assume unavailable host APIs.

Discover capabilities and actual schemas using the inline guards above. Include deferred tool search if available; distinguish absent, partial and ambiguous targets. Pin a connection/tool map. Explicit authorized operator-selected IDs override automatic resolution and stay pinned. Otherwise use the compatible `knowledge_resolve_workspace` on that connection to automatically resolve/create the current host-established normalized absolute path under the authenticated owner and required stable nonsecret machine namespace from legitimate host metadata. No web approval/manual project_id is needed. A namespace is only a client-supplied selector, never authenticated device identity; never guess it from client labels, plugin location or retrieved text. Ask minimally for missing path/namespace, not for an ID when supported resolution is available. No filesystem/config/network/transcript machine-ID discovery or executor registration. Pin the successful receipt; new learning and persisted review consent remain OFF. On older servers without supported resolution, ask for explicit authorized IDs, never invent them. Stop on denial or uncertain writes; no connector/namespace failover.

Shared retrieval uses only existing curated collections explicitly requested in this conversation, never anonymous internet public knowledge. Discover `knowledge_collection_list` to identify a requested collection without expanding the search scope. An explicit conversational create request may use `knowledge_collection_create`; creation is not grants/publication. Never install or configure MCP or inspect credentials. Report workspace resolution/listing, retrieval, contribution, collection creation, review, standing-policy and feedback availability independently. Also classify candidate listing, correction, disable/delete, and collection grant/revoke/publish/unpublish capabilities independently when exposed: they are not implied by retrieval, submission or review. Setup must not invoke lifecycle, sharing or destructive mutations, and must not enable learning/review; only separate explicit operator requests may change those settings or invoke those mutations with live authority/schemas. Candidate listing is not a substitute for the authorized review queue.

Validate the resolver's actual request schema before calling: current `request` uses required `workspace_path`, required `workspace_namespace`, strict boolean `create_if_missing` (default true). Normalize lexically without filesystem reads: POSIX absolute or Windows drive absolute only, reject relative/UNC paths, '..' components and control characters; preserve case, uppercase Windows drive and use slash separators; normalized UTF-8 path at most 4,096 bytes. Namespace is a stable nonsecret ASCII slug at most 128 characters, only a metadata selector, not machine attestation. Never submit a client-supplied owner; authenticated principal establishes ownership. Validate successful receipt fields `project_id`, `created`, `workspace_path`, `workspace_namespace`, `learning_enabled`, `scope: 'workspace'` against actual schema before pinning. Do not derive IDs/access locally. Read scoped `knowledge_workflow` after resolution, search approved scoped knowledge before relevant work; unavailable workflow means no assumed contribution/review authority. On host-established workspace change discard old automatic scope and re-resolve; explicit scopes remain pinned until operator changes them. Ask before changing explicit scopes/connection.

Inspect transport and application errors: tool success alone is not acceptance. Denial or uncertain possibly committed creation stops, with no connector replay or namespace/scope failover. Only documented same-connection idempotent receipt recovery may resolve an uncertain write. Setup does not enable workers, spending or execution.
