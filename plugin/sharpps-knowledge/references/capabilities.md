| Claude Code | `.claude-plugin/marketplace.json` package; `./skills/` | Traditional context-only command lifecycle hooks and read-only extractor/reviewer Markdown agents | Offline validator targeted installed 2.1.274; actual model participation/delegation not tested |
| Codex / ChatGPT | `.agents/plugins/marketplace.json`, `.codex-plugin/plugin.json`, `./skills/` | Explicit shared context-only hooks; no native agents declaration | Documented hook protocol, not runtime-tested; requires enabled/trusted supported runtime and available scripts, not web install alone; parent/manual separate role passes |
| Cursor | `.cursor-plugin/marketplace.json` and package manifest, `./skills/` | Explicit top-level self-contained `agents/cursor-knowledge-extractor.md` and `agents/cursor-knowledge-reviewer.md` with native `readonly: true` | Documented agent fields, not runtime-tested; no Cursor hooks supplied; Claude-specific `tools` field is not reused as native configuration |

| Claude web / skill-only hosts | Host-loaded canonical SKILL.md | Inline extraction rules, reviewer rubric and parent guards; no native agents required | No filesystem access or agents/ and references/ loading needed; separate same-context evaluative pass, not a subagent or independent check |
| Other hosts | Manually load canonical SKILL.md using host-supported mechanisms; references optional explanation only | None claimed | No invented native install/catalog/hook fields; verify host skill/tool support |

Partial tool sets remain useful. Compatible `knowledge_resolve_workspace` supports automatic current-workspace scope under authenticated owner + required stable host namespace + absolute path; explicit IDs override it. Missing/unsupported resolution on older servers needs explicit authorized IDs. `knowledge_list_workspaces` is bounded read-only metadata, not scope selection or consent. Namespace is a selector, not a verified device; client labels never determine ownership. Missing host metadata needs a minimal question, not guessed IDs. Shared retrieval is existing curated collections explicitly requested in conversation; compatible collection list/create capabilities do not imply grants/publication, and creation needs an explicit request. New workspace learning and persisted automatic-review consent independently default OFF. Workflow/search/get allow advisory retrieval; direct contribution additionally needs submit schema, permission and enabled learning. Manual review needs operator request plus review authority. Standing review needs persisted policy and guarded queue/automatic-review capabilities; older servers/storage must report unavailable. Feedback needs its own exposed compatible schema. Discovery cannot create authority, endpoints, identities or credentials.

For clients without verified delegation, canonical knowledge-learn and knowledge-review skills are self-contained: the parent performs an explicit extraction pass and a distinct evaluative review pass using the SAME MODEL / SAME CONTEXT with the inline rubric after extraction finishes, discloses weaker separation, and retains all guarded writes. No required filesystem reads, agents/ or references/ loading, fake subagent, independent check, independent rerun, second human or new identity. Never let the extractor silently autoapprove. Supported persisted enabled standing consent permits justified `approved_for_reuse` without per-candidate human confirmation after that distinct pass and live ACL/exact policy/version/state checks; honest `contributor_reported` provenance is not a blanket approval ceiling. Unknown/incomplete/truncated evidence and unsafe/conflicting claims stop/escalate. No adapter bundles MCP, makes raw network calls, scans credentials or adds native fields merely to suggest parity.

Native host-loaded roles remain optional self-contained support with no external reference Reads or loading acknowledgments. Missing native role files do not block the inline skill fallback. If a skill needs reloading, use the host-supported mechanism; do not list plugin directories, scan caches for `~g2`, guess cwd/cache paths or assume host APIs. Incomplete inline instructions block the role, not a brief-only approval downgrade. Nested `agents/cursor/*.md` files remain unchanged and unused by the manifest. Namespace labels select metadata, not machine attestation.

These are prompt-level workflow instructions, not runtime enforcement. Compatible server consent, ACL, exact policy/version/state revision checks and automatic-review evidence completeness are server-enforced; role loading does not enforce model behavior. Contributor-reported checks are not independently rerun. Connected OAuth operations use the connected account's authenticated principal, not a second human or identity. No measured cost/runtime improvement or provider-native runtime parity is claimed.
