Partial tool sets remain useful. All-accessible search is a narrow exception only for an explicit conversational request from the user to search all accessible knowledge, with compatible `all_accessible` (boolean, default false, mutually exclusive with project/collection IDs) discovered in the pinned connection's actual live SearchRequest schema. Send strict JSON boolean true and omit project_id/collection_ids. It includes owned/current exact READ-granted source projects and readable collections' current published nonprivate approved knowledge, not anonymous/public data. Do not perform project/scope/namespace/collection enumeration or automatic workspace creation/resolution in this mode. No source-project workflow is required when no source project is selected. Older absent/incompatible support must be explicitly reported unavailable, never emulated by enumeration or connector failover. Preserve collection-only get/feedback provenance and no source-project contribution/review authority; grants/publication/consent remain unchanged. Ordinary automatic retrieval stays workspace scoped and does not opt into global mode.

Compatible `knowledge_resolve_workspace` supports automatic current-workspace scope under authenticated owner + required stable host namespace + absolute path; explicit IDs override it. Missing/unsupported resolution on older servers needs explicit authorized IDs. `knowledge_list_workspaces` is bounded read-only metadata, not scope selection or consent. Namespace is a selector, not a verified device; client labels never determine ownership. Missing host metadata needs a minimal question, not guessed IDs. Shared retrieval is existing curated collections explicitly requested in conversation; compatible collection list/create capabilities do not imply grants/publication, and creation needs an explicit request. New workspace learning and persisted automatic-review consent independently default OFF. Workflow/search/get allow advisory retrieval; direct contribution additionally needs submit schema, permission and enabled learning. Manual review needs operator request plus review authority. Standing review needs persisted policy and guarded queue/automatic-review capabilities; older servers/storage must report unavailable. Feedback needs its own exposed compatible schema. Discovery cannot create authority, endpoints, identities or credentials.

For clients without verified delegation, canonical knowledge-learn and knowledge-review skills are self-contained: the parent performs an explicit extraction pass and a distinct evaluative review pass using the SAME MODEL / SAME CONTEXT with the inline rubric after extraction finishes, discloses weaker separation, and retains all guarded writes. No required filesystem reads, agents/ or references/ loading, fake subagent, independent check, independent rerun, second human or new identity. Never let the extractor silently autoapprove. Supported persisted enabled standing consent permits justified `approved_for_reuse` without per-candidate human confirmation after that distinct pass and live ACL/exact policy/version/state checks; honest `contributor_reported` provenance is not a blanket approval ceiling. Unknown/incomplete/truncated evidence and unsafe/conflicting claims stop/escalate. No adapter bundles MCP, makes raw network calls, scans credentials or adds native fields merely to suggest parity.

Native host-loaded roles remain optional self-contained support with no external reference Reads or loading acknowledgments. Missing native role files do not block the inline skill fallback. If a skill needs reloading, use the host-supported mechanism; do not list plugin directories, scan caches for `~g2`, guess cwd/cache paths or assume host APIs. Incomplete inline instructions block the role, not a brief-only approval downgrade. Nested `agents/cursor/*.md` files remain unchanged and unused by the manifest. Namespace labels select metadata, not machine attestation.

The client-led correction branch is also self-contained in skills: main-agent actual reuse observation (not mere retrieval), authorized exact-version/provenance feedback, original-lineage minimal correction draft, optional read-only draft challenge, parent-only guarded knowledge_correct, then DISTINCT separate review of the saved pending candidate. No unrelated new candidate submission replaces correction. Discover live CorrectInput/new_evidence support; fresh attachments require review+contribution+enabled learning and applicable task evidence-sharing permission, old-only retains legacy review-only behavior. Already explicit task-sharing authorization needs no repeated per-feedback prompt or new persisted consent flag; it is distinct from standing approval consent. Fresh-evidence-only correction is valid without retained IDs; authorized bounded reviewer views never justify widening ordinary retrieval/history enumeration. Missing prerequisites or unsafe essential evidence mean draft-only. Feedback/challenger agreement/correction authority grant no approval. Saved current_version pending can hide default/shared retrieval, and new collection publication needs separate authorization. Ten candidate/correction drafts combined per cycle; no background guarantees, stale auto-merge/retry or cross-connector fallback.

These are prompt-level workflow instructions, not runtime enforcement. Compatible server consent, ACL, exact policy/version/state revision checks and automatic-review evidence completeness are server-enforced; role loading does not enforce model behavior. Contributor-reported checks are not independently rerun. Connected OAuth operations use the connected account's authenticated principal, not a second human or identity. No measured cost/runtime improvement or provider-native runtime parity is claimed.
